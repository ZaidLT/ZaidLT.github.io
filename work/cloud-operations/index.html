As the only cloud engineer, I owned the collection platform's architecture, deployments and on-call. I built the shared Azure Functions runtime, run records and Fleetwatch monitoring to diagnose collection failures and misleading alerts.

I built 160 source collectors, with shared controls for scheduling, coverage measurements and actionable alerts.

Control scheduled execution

I used Azure timer triggers and renewable blob leases to coordinate scraper runs. A known lease conflict produced a recorded skipped execution, allowing operators to distinguish overlap prevention from a failed collection attempt.

I kept scheduling decisions tied to operating requirements: concurrency, overlap, retries and cost. Shared controls let the fleet evolve without introducing a separate scheduler before those requirements justified it.

Make each run inspectable

I added run records carrying scraper identity, timestamps, outcome and available collection or cost metrics. Individual JSON artifacts in Azure Blob Storage gave operators a record to inspect alongside application logs.

Fleetwatch combined a dashboard, snapshot API and alerts to show fleet health, coverage and the sources needing attention. Deployment preflight checks, rate limits and per-service cost tracking supported the day-to-day operating work.

Resolve the root cause behind the alerts

I traced misleading coverage alerts to held-document counts frozen at an earlier measurement date. Comparing those stale counts with current source totals made healthy sources appear deficient.

I corrected the count refresh and digest behavior, then checked the resulting attention list against the operational snapshot. Coverage comparisons used matching units, such as unique PDFs held and unique PDFs available.

On 24 August 2026, the attention list fell from 14 sources to 1. The result measured sources needing manual attention after the coverage and alert corrections.

Carry the operating knowledge forward

I developed monitoring, preflight checks, cost controls and runbooks so the collection platform could be operated and diagnosed consistently. These responsibilities connected the runtime implementation with the people maintaining it.

The infrastructure and migrations case covers my environment setup, infrastructure as code, access management, migrations and production recovery.
