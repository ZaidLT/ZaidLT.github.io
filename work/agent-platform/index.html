I co-led a 16-agent home operations platform and shipped seven production capabilities across document intelligence, persistent memory and service workflows.

At eeva, I co-led the platform with one other engineer, served as the primary memory-service engineer, owned voice and messaging, and built and deployed two MCP servers on Google Cloud Run.

Ship capabilities across the product journey

My seven production capabilities connected three parts of the product:

  • Document intelligence: scanning, document ingestion and answers grounded in source manuals.
  • Persistent memory: message storage and vectorisation, carrying useful context across conversations.
  • Service workflows: calling and repair flows that preserve the user's choices and pause for approval before external actions.

Together, these capabilities connected a user's request to household information, relevant tools and a recorded outcome.

Coordinate specialists with typed tools

I co-led the Google ADK runtime: one orchestrator routed work to 16 specialist agents across household services, appliances, vehicles, safety and other home-management domains. FastAPI services connected those agents to typed tools for product records, document retrieval, provider search, communications, calendars and device controls.

Account scope, session context and workflow state stayed attached to the task as specialists and tools took over different steps. This let a follow-up request use the appliance, provider or decision already established in the conversation.

Build persistent, relationship-aware memory

As the primary engineer on the standalone memory service, I combined PostgreSQL and pgvector with structured facts, semantic retrieval and time-dependent relationships. Hybrid retrieval brought memory and document results together for the task at hand.

I built context handling for facts that change: versioning, contradiction detection, expiration, category filtering and selective writes. Rolling summaries and token-budgeted compression preserved useful context within the model's input budget.

The memory layer connected user profiles and conversation context with document-derived entities and operational records. Entity extraction and a temporal knowledge graph retained relationships and their evolution. Gmail, Outlook and Calendar connectors supplied background events for deduplication, embeddings and fact extraction.

I also authored the memory evaluation harness, testing 303 facts against 729 queries across four configurations. OpenAI + Markdown reached 93.8% Recall@3 and 0.878 MRR@3.

Connect household records and document intelligence

PostgreSQL provided the household system of record: accounts, homes and assets, documents, service providers, maintenance activity and conversations. Tools could read and update those records, so a provider selection or maintenance recommendation became persistent product state.

The product accepted individual or batch uploads and processed 11 document families with Google Document AI, Azure Document Intelligence and Gemini Vision. Google Cloud Storage retained original uploads, while PostgreSQL held extracted fields and metadata for account-scoped retrieval.

The product upload flow complemented the separate Azure appliance-manuals platform, which acquired and prepared the reference corpus.

Own voice, messaging and service execution

I owned the voice and messaging integrations using Vapi, Twilio and ElevenLabs, with WebSocket and SSE streaming. Email, WhatsApp, LINE, SMS and voice connected requests, reminders, confirmations, provider cards and configured outbound calls to the platform.

I built the repair workflow's approval controls, typed inputs, account scoping, duplicate-action prevention and decision audit records. Persisted state carried the user's selection and consent across the workflow:

  1. Identify the problem and relevant appliance.
  2. Retrieve warranty, ownership and document context.
  3. Find providers and preserve the user's selection.
  4. Present the proposed action for explicit approval.
  5. Initiate the authorized call or scheduling action and record the outcome.

The walkthrough above demonstrates this approval boundary.

Extend the platform through integrations

I built and deployed two MCP servers on Google Cloud Run, exposing existing backend tools to other agent clients through typed interfaces.

The platform connected web, chat, uploads, voice and API entry points to shared household context. Home Assistant integration exposed device discovery and controls through REST and MQTT. The vehicle pipeline connected VIN validation, recall data and maintenance recommendations to tasks and events.

Separate containers for the backend, frontend and memory service supported deployment and integration work. My role carried across those boundaries: building AI capabilities, connecting product services and operating the cloud infrastructure behind them.
