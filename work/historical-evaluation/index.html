Problem

Outcome
OpenAI + Markdown reached 93.8% Recall@3 and 0.878 MRR@3 on 729 queries; configuration and category reports supported the selection.

I authored a retrieval evaluation harness that tested 303 facts against 729 queries across four model and data-format configurations. The OpenAI + Markdown configuration reached 93.8% Recall@3 and 0.878 MRR@3.

I built the harness and ran the experiment to guide memory retrieval for the agent platform. It scored expected facts, reported individual query outcomes and compared performance across direct, paraphrased, temporal and adversarial questions.

Turn retrieval results into a configuration decision

I compared OpenAI and Google embeddings with JSON and Markdown representations, keeping the facts and query set consistent across configurations. Aggregate scores established the overall result, while category reports showed where ranking behavior changed.

OpenAI + Markdown led on Recall@1, which informed the retained report's recommendation. Google + JSON led on Recall@3. That distinction made configuration choice depend on how the agent consumed retrieved evidence.

Experiment and construction

The report was generated on 10 April 2026. It evaluated 303 home-management facts, including 110 adversarial facts, against 729 queries. Local fact definitions and a query-construction module produced this internal benchmark and its expected-fact mappings.

Each query identified one expected fact ID. The same facts were represented as JSON or Markdown. Each model/configuration used its own pgvector table; queries remained plain text. Retrieval used cosine distance and returned three candidates.

  • OpenAI: text-embedding-3-large, 3,072 dimensions.
  • Google: models/gemini-embedding-001, 3,072 dimensions.
  • Recall@1 / Recall@3: fraction of queries with the expected fact in that prefix.
  • MRR@3: reciprocal rank of that fact within the first three results, zero when absent.

The report's MRR values are shown as MRR@3, reflecting its three-result cutoff.
